# Aria Internal v0.1.3

> 本文是 [`v0.1.3.md`](v0.1.3.md) 的中文版。

Aria 0.1.3 引入了GitHub Release 安装与升级渠道。它仅通过本仓库
不可变的 GitHub Release 分发，不发布到 npm。

## 亮点

- 新增由已认证的 GitHub CLI 支撑的独立引导安装器。
- 新增版本化安装，对外暴露稳定的 `aria` 启动器。
- 新增事务化的升级、回滚与操作状态命令。
- 新增分离式（detached）OS 升级执行器，daemon 可以安全地替换并重启自己的
  服务定义。
- 新增与精确构建 commit 绑定的五资产发布契约校验。

## 安装与升级架构

- 可执行版本、升级计划、下载与操作日志存放在 `ARIA_INSTALL_HOME` 下，与
  `ARIA_HOME` 中的 profile 状态相互独立。
- GitHub 凭证始终由 `gh` 持有；Aria 不读取也不持久化 token。
- 消费方只接受已发布的不可变 `internal-v*` 预发布版本，且必须包含完整的
  tarball、产物 manifest、校验文件、发布 manifest 与独立安装器。
- 安装前会交叉校验发布元数据、tag commit、包 manifest、校验声明与下载的
  tarball 字节。
- 新版本先装入 staging，经冒烟测试后原子提升，再通过 `install.json` 选定。

## 运行时安全与回滚

- `aria update plan` 会快照所选发布版本与受影响的服务。
- `aria update apply` 在切换前立即复核发布字节、进行中的工作与服务状态。
- Linux、macOS 与 Windows 使用分离式升级执行器，重启 Aria 不会终止升级器。
- 健康检查失败会恢复此前的启动器目标、服务定义与运行版本。
- 已有的 npm 或 pnpm 全局安装保留为初始回滚基线；不会自动删除任何遗留
  文件。

## 命令

- `aria update check`
- `aria update plan`
- `aria update apply <plan-id>`
- `aria update status <operation-id>`
- `aria update rollback`

## 兼容性

- 现有 profile、凭证、会话、日志与工作空间全部保留。
- 包仍然仅通过 GitHub Releases 分发，不发布到 npm。
- 可变的旧版 `internal-v0.1.2` release 保持原样，并会被新的不可变发布
  来源忽略。

## 已知限制

- 未启用自动后台升级策略；升级由用户主动发起。
- 本版本不包含飞书/Lark 与 web 端的升级控制。
- 后续的可消费 release 必须保持仓库 Release 不可变设置开启。

## 包含的变更

- #30 / #31：GitHub Release 安装器、升级器与回滚架构。
- #32：不可变 internal v0.1.3 发布的准备与上线。
