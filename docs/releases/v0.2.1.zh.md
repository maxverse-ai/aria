# Aria Internal v0.2.1

> 本文是 [`v0.2.1.md`](v0.2.1.md) 的中文版。

Aria 0.2.1 在 0.2 稳定线上完成了第一个具备生产能力的触发平台。它把
0.2.0 引入的只读触发契约变成持久、可恢复、渠道中立的执行系统，同时保持
Supervisor 作为唯一的运行时宿主。

本内部快照通过 GitHub 仓库分发，不发布到 npm。

## 新增

- 新增持久化的定时定义、发生实例、租约、执行结果、审计记录、恢复、
  幂等与重复周期计算。
- 新增 Supervisor 持有的触发管理器：发现到期实例、认领、创建校验过的
  `RunIntent`，并通过现有 agent 运行时派发工作，而非引入第二个执行器。
- 新增结果路由：支持仅记录历史的运行与渠道中立的会话投递，带持久化
  投递检查点与重试。
- 新增管理 API 与 `aria trigger` CLI 操作：定时任务的规划、创建、查看、
  更新、暂停、恢复、推迟、运行与取消，以及历史与审计查看。
- 新增会话提醒的解析与确认流程，定时存储与执行不与 Lark 耦合。
- 新增有作用域、可过期的 bearer 授权，agent 可以通过同一 API 边界管理
  提醒，而无需直接访问文件系统、数据库或定时器。
- 新增合成推送提供方参考实现与端到端扩展证明，覆盖提供方入口、持久化
  实例创建、重启稳定的去重、执行与生命周期排空。

## 控制台与运维

- 在独立的 Supervisor 控制台中新增基于 Astryx 的触发视图：定时任务、
  历史、审计数据、运行时状态与管理操作。
- 新增部署诊断与运行时能力元数据，支持通过 `ARIA_TRIGGER_RUNTIME=enabled`
  分阶段启用。
- 触发平台保持不依赖任何单一渠道：Lark 与未来的来源在入口和投递边界
  都只是适配器。

## 安全与恢复

- 定时变更由管理层校验并在应答前持久化；CLI 是该边界的适配器，而不是
  另一个状态持有方。
- 不承诺恰好一次的副作用。系统提供持久化的至少一次执行：幂等的实例
  物化、租约、隔离栅栏、重试策略与可审计的终态结果。
- 外部提供方身份只是证据，绝不是权威。提供方、profile、实例、来源类型
  与作用域绑定必须与持久化的有效定义匹配，入口才会被接受。
- Agent 授权约束 profile、引擎、主体、定时类型、频率、有效期与操作
  范围。授权密钥只显示一次，仅持久化其摘要。

## 升级指引

- 全局安装从 0.1.6 或 0.2.0 通过常规 `aria update` plan/apply 流程升级，
  请先等活动会话排空。
- 使用 `ARIA_TRIGGER_RUNTIME=enabled` 显式启用定时执行；定义与历史在
  Supervisor 重启后依然持久。
- 保持现有渠道 profile 不变。触发来源与结果出口通过已注册的适配器和
  现有 profile/运行时模型解析。
- 在 Supervisor、控制台、触发运行时与渠道健康检查通过前，保留升级器
  先前的活动版本作为自动回滚目标。
