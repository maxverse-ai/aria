# Aria v0.4.5

> 中文版：[v0.4.5.zh.md](v0.4.5.zh.md)

Aria 0.4.5 improves Windows daemon autostart reliability and private GitHub Release verification.

## Fixed

- Starting the Windows daemon preserves existing scheduled tasks and saved boot credentials by default while refreshing the launcher.
- Windows task state is queried through COM/XML, avoiding dependence on English scheduler output.
- Task startup stops when enabling the task fails, and new registrations are verified before success is reported.
- Host-local publication inspects private release drafts by release ID before publishing the verified assets.
- Embedded worker tests isolate inherited channel environment variables and verify that worker startup still rejects them.

## Windows autostart

`aria start --autostart auto|boot|logon` selects the startup mode. The default `auto` preserves an existing task; for a new task it selects boot startup in an elevated interactive terminal and logon startup otherwise.

Boot setup requires a local Administrator terminal and the Windows account password, rather than a Windows Hello PIN. Explicit `boot` setup never silently falls back to logon startup. Cancelling credential input in `auto` mode allows logon setup.

`aria status`, including JSON output, reports the actual registered autostart mode. Existing logon tasks remain logon tasks until explicitly changed with `aria start --autostart boot`.

See the [bridge operations guide](../operate-the-bridge.md) for setup details and the [release policy](../RELEASE_POLICY.md) for the verified host-local publication process.
