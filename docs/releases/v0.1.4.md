# Aria Internal v0.1.4

> 中文版：[v0.1.4.zh.md](v0.1.4.zh.md)

Aria 0.1.4 repairs the private GitHub Release bootstrap boundary introduced in
0.1.3. The Release installer is now a genuinely standalone ESM file and is
verified from a dependency-free temporary directory before publication.

This internal snapshot is distributed through the private GitHub repository. It
is not published to npm.

## Fixed

- Bundled all non-Node runtime dependencies into `aria-install.mjs` while
  keeping the ordinary CLI and updater on their normal packaged dependency
  model.
- Added the native ESM `createRequire` bridge needed by bundled CommonJS
  dependencies such as `cross-spawn`.
- Extended candidate artifact verification to copy the packaged installer into
  a clean temporary directory and execute `--help` there.
- Repeated the same isolation check on the exact installer bytes prepared for
  GitHub Release upload.

## Upgrade guidance

- Use `internal-v0.1.4` for new installations and migrations from legacy global
  npm/pnpm installations.
- Do not use the `internal-v0.1.3` standalone installer: that immutable asset
  externalizes runtime packages and cannot start from a clean directory.
- Existing 0.1.3 package installations that already have their dependency tree
  are not rewritten in place; the supported correction is the normal update to
  0.1.4.

## Distribution guarantees

- The internal release is created only from the exact merged `main` commit.
- The tarball, artifact manifest, checksum file, release contract, and
  standalone installer are verified before the draft is published.
- Repository-level GitHub Release immutability prevents replacement of the tag
  or uploaded assets after publication.
- Legacy global installations remain available as the initial rollback
  baseline during migration.

- Full unit, integration, process, and static contract suite.
- TypeScript typecheck and production builds for CLI, installer, updater, and

- Candidate tarball installation with lifecycle scripts disabled.
- Standalone installer execution from an isolated directory containing no
