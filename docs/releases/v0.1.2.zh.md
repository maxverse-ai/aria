# Aria Internal v0.1.2

> 本文是 [`v0.1.2.md`](v0.1.2.md) 的中文版。

Aria 0.1.2 是一个私有内部架构与工作空间治理快照。它仅通过本仓库的
GitHub Release 分发，不发布到 npm。

## 亮点

- 确立了独立的状态根目录与受管工作空间路径契约。
- 为 Aria 受管的默认工作空间增加了安全、幂等的初始化。
- 减少了常规 profile 启动过程中的隐式文件系统改动。
- 增加了布局版本化与无变更迁移规划的基础设施。
- 增加了可插拔的微信客服入口，以及可复用的非 Lark profile 会话组装。

## 工作空间与状态布局

- 新增可独立配置的 `ARIA_HOME` 与 `ARIA_WORKSPACE_HOME` 根目录。
- 保留 `LARK_CHANNEL_HOME` 与旧版 `rootDir` 兼容行为。
- 新增类型化路径：profile 身份、持久状态、引擎数据、缓存、日志、运行时
  文件与受管工作空间。
- 从核心 profile 引导中移除了引擎专属的 `codex-home` 创建。

新的 Aria 受管默认工作空间包含身份中立的 `AGENTS.md`、`README.md` 和
`scratch/`。初始化是幂等的，不会覆盖自定义内容，会拒绝不安全的符号链接
目标，并且永远不会为显式选择的用户项目生成脚手架。

## 渠道架构

- 新增持久的微信客服回调入口与协议适配器。
- 新增可插拔的会话运行时边界。
- 新增 `ProfileConversationHost`，非 Lark 渠道可以复用 profile 的 agent、
  策略、工作空间与会话行为，而无需再开一个 Lark 传输层。
- 新增确定性的生命周期清理与隔离的渠道会话状态。

## 兼容性

- 现有 profile 与 `LARK_CHANNEL_HOME` 兼容根目录继续可用。
- 现有状态不会被自动迁移。
- 显式指定的用户工作空间会被校验并记录，但绝不会被改写。
- 本内部快照不会发布或修改 npm registry 中的任何内容。

## 已知限制

- 现有 profile 仍使用兼容的物理布局。
- 物理状态迁移、加锁、校验与回滚执行仍是后续工作；本版本只提供路径契约
  与迁移计划。

## 包含的变更

- #3：受管工作空间布局实现。
