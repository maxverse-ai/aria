# Aria Internal v0.1.3

Aria 0.1.3 introduces the private GitHub Release installation and update
channel. It is distributed only through this repository's immutable GitHub
Release and is not published to npm.

## Highlights

- Added a standalone bootstrap installer backed by authenticated GitHub CLI.
- Added versioned installations behind a stable `aria` launcher.
- Added transactional update, rollback, and operation-status commands.
- Added detached OS update execution so a daemon can safely replace and restart
  its own service definition.
- Added a verified five-asset release contract bound to the exact build commit.

## Installation and update architecture

- Executable versions, plans, downloads, and operation journals live under
  `ARIA_INSTALL_HOME`, independently from profile state in `ARIA_HOME`.
- GitHub credentials remain owned by `gh`; Aria does not read or persist tokens.
- Consumers accept only published immutable `internal-v*` prereleases with a
  complete tarball, artifact manifest, checksum file, release manifest, and
  standalone installer.
- Release metadata, tag commit, package manifest, checksum declaration, and
  downloaded tarball bytes are cross-checked before installation.
- New versions are installed into staging, smoke-tested, atomically promoted,
  and selected through `install.json`.

## Runtime safety and rollback

- `aria update plan` snapshots the selected release and affected services.
- `aria update apply` rechecks release bytes, active work, and service state
  immediately before switching.
- Linux, macOS, and Windows use detached update executors so restarting Aria
  cannot terminate the updater.
- A failed health check restores the prior launcher target, service definition,
  and running version.
- Existing npm or pnpm global installs are retained as the initial rollback
  baseline; no legacy files are deleted automatically.

## Commands

- `aria update check`
- `aria update plan`
- `aria update apply <plan-id>`
- `aria update status <operation-id>`
- `aria update rollback`

## Compatibility

- Existing profiles, credentials, sessions, logs, and workspaces are preserved.
- The package remains private to GitHub Releases and is not published to npm.
- The mutable legacy `internal-v0.1.2` release remains untouched and is ignored
  by the new immutable-release source.

## Known limitations

- Automatic background update policy is not enabled; updates are user-initiated.
- Feishu/Lark and web update controls are not included in this release.
- Repository Release immutability must remain enabled for future consumable
  releases.
