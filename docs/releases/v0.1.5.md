# Aria Internal v0.1.5

> 中文版：[v0.1.5.zh.md](v0.1.5.zh.md)

Aria 0.1.5 strengthens the runtime boundary used by external channels and
diagnostic consumers. It adds an extensible engine contract, expands Native
Read projections, and makes the WeChat Customer Service path durable across
answer generation, delivery, and image handling.

This internal snapshot is distributed through the GitHub repository. It
is not published to npm.

## Added

- Defined a capability-driven Agent runtime contract so engine-specific model,
  reasoning, service-tier, and session behavior can evolve without spreading
  engine conditionals through the channel layer.
- Joined message identities and session catalog data into Native Read while
  preserving the read-only diagnostic boundary.
- Added deterministic WeChat Customer Service session commands and injectable,
  channel-specific presentation rules.
- Added inbound JPG/PNG attachment ingestion and durable outbound image
  delivery through the shared media boundary.

## Reliability

- Checkpointed generated WeChat Customer Service answers before delivery so a
  transient send failure does not lose completed work.
- Added durable receipts, inbox state, onboarding state, and delivery recovery
  for the WeChat Customer Service channel.
- Rendered outbound WeChat Customer Service text through a dedicated plain-text
  presentation adapter and kept processing feedback scoped to eligible
  questions.
- Restored Native Read HTTP startup across Linux, macOS, and Windows by using a
  short POSIX socket path and the native Windows named-pipe path.
- Made background card-action tests wait on the registered completion boundary
  and bounded Windows test parallelism to remove scheduling-dependent failures.

## Upgrade guidance

- Use `internal-v0.1.5` for global Aria installations after the normal update
  preflight reports that no conversation is active.
- Treat the update as an Aria runtime update only. Deploying channel-specific
  channel-specific consumers remains a separate operational decision.
- Keep the previous immutable internal release installed as the automatic
  rollback baseline until post-update health checks pass.

## Distribution guarantees

- The internal release is created only from the exact merged `main` commit.
- The tarball, artifact manifest, checksum file, release contract, and
  standalone installer are verified before the draft is published.
- Repository-level GitHub Release immutability prevents replacement of the tag
  or uploaded assets after publication.
- The updater performs a planned version switch with restart safety checks,
  health verification, and rollback support.
