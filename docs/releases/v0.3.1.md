# Aria Internal v0.3.1

Aria 0.3.1 is a patch on the 0.3 line. It fixes the detached Linux updater's
GitHub identity boundary and carries everything delivered on this line: the
Trigger Platform inherited from 0.2.1 / 0.2.2, execution spaces, the
channel-free managed worker, the `/task` conversation commands, per-engine
permission policy, the console development preview, and channel profile schema
v3 as an explicit opt-in migration.

This internal snapshot is distributed through the private GitHub repository. It
is not published to npm.

## Fixed

- The Linux detached updater now forwards `GH_CONFIG_DIR` into the transient
  `systemd-run --user` unit. `systemd-run` starts from the user manager's
  environment rather than the invoking CLI's, so the updater lost the isolated
  GitHub CLI configuration and failed closed during private-release
  revalidation — before any version switch. The previous installation stayed
  active and remained the rollback baseline.
- Only the authenticated GitHub CLI configuration directory is passed. Bearer
  material such as `GH_TOKEN` is deliberately never copied into systemd unit
  metadata or process arguments, and a regression assertion holds that
  boundary.

## Upgrade guidance

- Plan the exact version with `aria update plan --target-version 0.3.1`, then
  apply the generated plan. Use the 0.3.1 CLI for both planning and applying.
- Set `GH_CONFIG_DIR` in the invoking environment to the operator's
  authenticated GitHub CLI configuration directory before planning or applying.
  Do not print it, call `gh auth token`, or pass a bearer token on a command
  line.
- Do not retry an update plan that already failed on the identity boundary.
  Create a fresh plan against this release instead.
- Keep the immutable `internal-v0.2.2` installation as the rollback baseline
  until supervisor, profile, channel, and console health checks pass.
