# Aria Internal v0.1.6

Aria 0.1.6 expands the engine and channel extension boundaries, makes
conversation ownership explicit at the profile runtime, and allows the full
supervisor console to be exposed safely behind an authenticated path-based
reverse proxy.

This internal snapshot is distributed through the private GitHub repository. It
is not published to npm.

## Added

- Added the Grok engine through its structured agent-stdio protocol, including
  history discovery, permission handling, steering, model metadata, and CLI
  argument passthrough.
- Defined Channel Plugin ABI v1 with manifest validation, runtime registration,
  lifecycle contracts, typed errors, and a reusable contract-test kit.
- Added deployment-safe console settings for a fixed loopback port, an explicit
  upstream token file, and exact trusted proxy origins.
- Added a reverse-proxy deployment contract for mounting the complete supervisor
  console below a URL path while keeping human authentication at the edge and
  the upstream token private to the host.

## Runtime and reliability

- Made the conversation runtime profile-owned so reconnects preserve one
  authoritative conversation host while profile stop still closes it cleanly.
- Isolated reconnect tests from host-installed agent binaries so supervisor CI
  remains deterministic on clean Linux, macOS, and Windows runners.
- Kept the console secure by default: loopback binding remains mandatory,
  localhost origins remain the default, token-file permissions are validated,
  and proxy origins require exact matches.
- Made browser API resolution relative to the mounted console directory so a
  path such as `/aria/` stays independent from applications served at the domain
  root.

## Upgrade guidance

- Use `internal-v0.1.6` for global Aria installations after the normal update
  preflight reports that no conversation is active.
- A path-mounted console should run behind an authenticated reverse proxy. Do
  not expose its loopback service directly or place the upstream token in
  browser-visible configuration.
- Preserve the previous immutable `internal-v0.1.5` installation as the
  automatic rollback baseline until supervisor, profile, and console health
  checks pass.
- Treat reverse-proxy configuration and any consumer deployment as separate
  operational changes from installing the Aria runtime.

## Distribution guarantees

- The internal release is created only from the exact merged `main` commit.
- The tarball, artifact manifest, checksum file, release contract, and
  standalone installer are verified before the draft is published.
- Repository-level GitHub Release immutability prevents replacement of the tag
  or uploaded assets after publication.
- The updater performs a planned version switch with restart safety checks,
  health verification, and rollback support.
