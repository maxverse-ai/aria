# Aria Internal v0.1.2

> 中文版：[v0.1.2.zh.md](v0.1.2.zh.md)

Aria 0.1.2 is a private internal architecture and workspace-governance snapshot.
It is distributed only through this repository's GitHub Release and is not
published to npm.

## Highlights

- Established independent state-root and managed-workspace path contracts.
- Added safe, idempotent initialization for Aria-managed default workspaces.
- Reduced implicit filesystem mutation during ordinary profile startup.
- Added layout versioning and mutation-free migration planning foundations.
- Added a pluggable WeChat Customer Service ingress and reusable non-Lark
  profile conversation composition.

## Workspace and state layout

- Added independently configurable `ARIA_HOME` and `ARIA_WORKSPACE_HOME` roots.
- Preserved `LARK_CHANNEL_HOME` and legacy `rootDir` compatibility behavior.
- Added typed paths for profile identity, persistent state, engine data, cache,
  logs, runtime files, and managed workspaces.
- Removed engine-specific `codex-home` creation from core profile bootstrap.

New Aria-managed default workspaces contain an identity-neutral `AGENTS.md`,
`README.md`, and `scratch/`. Initialization is idempotent, does not overwrite
custom content, rejects unsafe symbolic-link targets, and never scaffolds an
explicitly selected user project.

## Channel architecture

- Added a durable WeChat Customer Service callback ingress and protocol adapter.
- Added a pluggable conversation-runtime boundary.
- Added `ProfileConversationHost` so non-Lark channels can reuse profile agent,
  policy, workspace, and session behavior without opening another Lark transport.
- Added deterministic lifecycle cleanup and isolated channel session state.

## Compatibility

- Existing profiles and the `LARK_CHANNEL_HOME` compatibility root continue to work.
- Existing state is not moved automatically.
- Explicit user workspaces are validated and recorded but never rewritten.
- This internal snapshot does not publish or modify anything in the npm registry.

## Known limitations

- Existing profiles still use the compatibility physical layout.
- Physical state migration, locking, verification, and rollback execution remain
  future work; this release provides the path contracts and migration plan only.
