# Aria Internal v0.1.4

> 本文是 [`v0.1.4.md`](v0.1.4.md) 的中文版。

Aria 0.1.4 修复了 0.1.3 引入的GitHub Release 引导安装边界。Release
安装器现在是一个真正独立的 ESM 文件，并且会在发布前于无依赖的临时目录中
完成验证。

本内部快照通过 GitHub 仓库分发，不发布到 npm。

## 修复

- 将所有非 Node 运行时依赖打包进 `aria-install.mjs`，同时让普通 CLI 与
  升级器继续使用正常的打包依赖模型。
- 为 `cross-spawn` 等打包的 CommonJS 依赖补充了原生 ESM `createRequire`
  桥接。
- 扩展了候选产物验证：把打包好的安装器复制到干净的临时目录中执行
  `--help`。
- 对准备上传 GitHub Release 的安装器字节重复执行了相同的隔离检查。

## 升级指引

- 新安装以及从旧版全局 npm/pnpm 安装迁移，请使用 `internal-v0.1.4`。
- 不要使用 `internal-v0.1.3` 的独立安装器：该不可变资产外置了运行时
  依赖包，无法从干净目录启动。
- 已具备完整依赖树的 0.1.3 包安装不会被原地改写；受支持的修正方式是
  正常升级到 0.1.4。

## 分发保证

- 内部发布仅从精确合入的 `main` commit 构建。
- tarball、产物 manifest、校验文件、发布契约与独立安装器在上传前均已
  验证。
- 仓库级 GitHub Release 不可变设置，确保发布后 tag 与上传资产无法被
  替换。
- 迁移期间，旧版全局安装仍保留为初始回滚基线。
