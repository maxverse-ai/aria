# Aria Internal v0.1.6

> 本文是 [`v0.1.6.md`](v0.1.6.md) 的中文版。

Aria 0.1.6 扩展了引擎与渠道的扩展边界，让会话归属在 profile 运行时层
显式化，并允许完整的 supervisor 控制台安全地暴露在带认证的路径前缀
反向代理之后。

本内部快照通过 GitHub 仓库分发，不发布到 npm。

## 新增

- 通过结构化 agent-stdio 协议新增 Grok 引擎，包括历史发现、权限处理、
  steering、模型元数据与 CLI 参数透传。
- 定义 Channel Plugin ABI v1：manifest 校验、运行时注册、生命周期契约、
  类型化错误与可复用的契约测试套件。
- 新增部署安全的控制台设置：固定 loopback 端口、显式上游 token 文件与
  精确匹配的受信代理来源。
- 新增反向代理部署契约：可以把完整 supervisor 控制台挂载在 URL 路径下，
  同时在边缘保留人类认证、上游 token 仅主机可见。

## 运行时与可靠性

- 会话运行时改为 profile 持有：重连后仍保留唯一的权威会话宿主，而
  profile 停止时仍会干净地关闭它。
- 重连测试与主机已安装的 agent 二进制隔离，supervisor CI 在干净的
  Linux、macOS 与 Windows runner 上保持确定性。
- 控制台保持默认安全：loopback 绑定仍为强制，localhost 来源仍为默认，
  token 文件权限会被校验，代理来源要求精确匹配。
- 浏览器 API 解析改为相对于控制台挂载目录，`/aria/` 这类路径不再与
  域名根部的其他应用相互干扰。

## 升级指引

- 在常规升级预检确认没有进行中的会话后，全局 Aria 安装请使用
  `internal-v0.1.6`。
- 路径挂载的控制台应运行在带认证的反向代理之后。不要直接暴露其
  loopback 服务，也不要把上游 token 放进浏览器可见的配置。
- 在 supervisor、profile 与控制台健康检查通过前，保留上一个不可变
  `internal-v0.1.5` 安装作为自动回滚基线。
- 反向代理配置与任何消费方部署，都是独立于 Aria 运行时安装的运维变更。
