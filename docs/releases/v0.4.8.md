# Aria v0.4.8

> 中文版：[v0.4.8.zh.md](v0.4.8.zh.md)

Aria 0.4.8 improves Codex session preparation and prevents a stopped run from submitting a task when a delayed resume response arrives.

- Existing-thread execution requests metadata-only resume responses and uses a separate 60-second resume deadline. Model, working directory, sandbox and service-tier settings remain part of the request.
- Stopping during session preparation ends the local wait and prevents subsequent task submission, including after outer execution capacity has been released. It does not claim to cancel the server-side resume operation.
- Resume timeouts explain that the new task has not been submitted and retain the original session association. Submission timeouts report uncertain acceptance and do not automatically resend input.
- RPC diagnostics record duration, response bytes and late responses without request or history bodies. Abandoned-request metadata is bounded and expires; one slow resume does not restart the shared process.
- Controlled stdio regressions and TLA+ model checks cover stop/resume races, late responses, concurrent sessions, resource cleanup and reconnect behavior.

Real long-session latency improvements and context continuity still require verification with isolated native session data. Synthetic tests and model checks are not production performance measurements. See [verification scope and evidence](../CODEX_RESUME_VERIFICATION.md).
