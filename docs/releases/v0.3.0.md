# Aria Internal v0.3.0

> 中文版：[v0.3.0.zh.md](v0.3.0.zh.md)

Aria 0.3.0 moves the release line from 0.2 to 0.3. It adds execution spaces, a
channel-free managed worker, and the permission, task and console work that
supports them.

Execution spaces are explicit. Nothing migrates automatically, they require
`mode: team`, and existing profile data stays sealed until a trusted adapter
imports it.

Execution spaces require a Linux host. Preparing or reading one elsewhere fails
closed with `execution spaces require a Linux host` instead of degrading.

This internal snapshot is distributed through the GitHub repository. It
is not published to npm.

## Added

- Added `aria space` for the execution-space lifecycle: `status`, `rollback`,
  `prepare <deployment-file>`, `prepare-upgrade <deployment-file>`,
  `activate <selection-file>`, and `inspect <selection-file>`. Preparation is
  offline and reviewable; activation happens while the profile is stopped.
- Added `aria worker discover` and `aria worker serve`, which run Aria as a
  channel-free managed worker speaking newline-delimited JSON-RPC over
  stdin/stdout.
- Added `aria profile start <name>`. Interactive `aria profile create` now
  starts the new profile on the existing Supervisor; `--no-start` saves without
  starting, and non-interactive scripts save only unless they pass `--start`.
- Added the `/task` conversation commands for admitted multi-participant work:
  `ask`, `join`, `leave`, `list`, `status`, `notes`, `transcript`, `change`,
  `use`, `save`, `remove`, `submit`, `stop`, and `cancel`.
- Added per-engine permission policy and the execution-space process boundary
  that native engine runtimes launch through.
- Added the console development preview, which serves the same `web/` source as
  the packaged console with a read-only default and an explicit write guard.

## Changed

- Removed the `bubblewrap` execution-space driver. `trusted-process` and the
  container (`execution`) driver remain; a deployment that omits the driver, or
  names an unknown one, is rejected rather than run unconfined.
- Execution spaces are declared Linux-only. The remaining space hosts were
  never able to satisfy the feature's unix-socket transport and container
  driver, and previously failed with an unrelated bind or path error.
- Channel profile schema v3 is available as an explicit opt-in migration.
  Schema v2 remains the default, reads never rewrite bytes, and no live profile
  migrates implicitly.
- A profile whose Supervisor startup fails keeps its saved configuration and
  reports the retry command instead of discarding the profile.
- Supervisor restarts restore only the profiles explicitly requested to run.
  Profiles explicitly stopped remain stopped.

## Upgrade guidance

- Existing Lark profiles need no changes. Execution spaces are an explicit
  prepare-and-activate step, never an automatic migration.
- A deployment that declares `driver: "bubblewrap"` must move to
  `trusted-process` (space-owned state, shared host OS access) or to the
  container driver (isolated). `trusted-process` does not establish an OS or
  credential isolation boundary.
- Prepare and inspect a deployment file from an isolated workspace. Do not edit
  an installed runtime.
- Treat the console preview as a development surface. It and the packaged
  console share `web/` and must not drift apart.
- Keep the immutable `internal-v0.2.2` installation as the rollback baseline
  until supervisor, profile, channel and console health checks pass.
