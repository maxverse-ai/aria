# Aria Internal v0.3.1

> 本文是 [`v0.3.1.md`](v0.3.1.md) 的中文版。

Aria 0.3.1 是 0.3 线上的一个补丁。它修复了 Linux 分离式升级器的 GitHub
身份边界问题，并携带本线上已交付的全部内容：从 0.2.1 / 0.2.2 继承的
触发平台、执行空间、无渠道受管 worker、`/task` 会话命令、按引擎权限
策略、控制台开发预览，以及作为显式 opt-in 迁移的渠道 profile schema v3。

本内部快照通过私有 GitHub 仓库分发，不发布到 npm。

## 修复

- Linux 分离式升级器现在会把 `GH_CONFIG_DIR` 转发进临时的
  `systemd-run --user` 单元。`systemd-run` 从用户管理器的环境启动，而非
  调用方 CLI 的环境，因此升级器此前会丢失隔离的 GitHub CLI 配置，并在
  私有发布重新校验时关闭失败——发生在任何版本切换之前。此前的安装保持
  活动，仍是回滚基线。
- 只有已认证的 GitHub CLI 配置目录会被传递。`GH_TOKEN` 这类 bearer 材料
  被刻意地绝不复制进 systemd 单元元数据或进程参数，并有回归断言守住
  这条边界。

## 升级指引

- 用 `aria update plan --target-version 0.3.1` 规划精确版本，然后应用
  生成的计划。规划与应用都使用 0.3.1 的 CLI。
- 在规划或应用之前，在调用环境中把 `GH_CONFIG_DIR` 设为运维者已认证的
  GitHub CLI 配置目录。不要打印它，不要调用 `gh auth token`，也不要在
  命令行上传递 bearer token。
- 不要重试已经在身份边界上失败的升级计划，改为针对本版本创建一个新
  计划。
- 在 supervisor、profile、渠道与控制台健康检查通过前，保留不可变的
  `internal-v0.2.2` 安装作为回滚基线。
