# Aria Internal v0.2.0

> 中文版：[v0.2.0.zh.md](v0.2.0.zh.md)

Aria 0.2.0 establishes the shared channel reliability layer, introduces the
first read-only trigger-platform contracts, and refreshes the supervisor
console on the Astryx design system.

This internal snapshot is distributed through the private GitHub repository. It
is not published to npm.

## Added

- Added `aria trigger capabilities` and `aria trigger schema <name>` for
  discovering versioned trigger contracts. Scheduled execution remains
  disabled in this release.
- Added the execution-intent catalog, schemas, validation, and conversation
  adapter as the foundation for future trigger providers.
- Defined the trigger provider ABI, registration contract, and contract-test
  kit without enabling provider execution.
- Added shared channel reliability primitives for leases, retries, delivery
  checkpoints, durable file-backed state, and in-memory contract testing.
- Added channel-instance resolution and explicit Lark conversation ownership
  projection at runtime.
- Added WeChat Customer Service channel-plugin composition, ownership, and a
  reliable message sink built on the shared channel contracts.

## Console and operations

- Replaced the previous supervisor console component layer with Astryx and
  refreshed configuration, onboarding, profile, and runtime views.
- Extended the read-only control plane with the channel and trigger state needed
  by the new console and platform contracts.
- Added browser typechecking to the required repository typecheck gate.

## Upgrade guidance

- Use `internal-v0.2.0` for global Aria installations after the normal update
  preflight reports that no conversation is active.
- Treat the trigger CLI as contract discovery only; this release does not run
  schedules or external trigger providers.
- Existing Lark profiles continue to use their current channel configuration;
  the new ownership projection and reliability layer are additive runtime
  foundations.
- Preserve the immutable `internal-v0.1.6` installation as the automatic
  rollback baseline until supervisor, profile, channel, and console health
  checks pass.

## Distribution guarantees

- The internal release is created only from the exact merged `main` commit.
- The tarball, artifact manifest, checksum file, release contract, and
  standalone installer are verified before the draft is published.
- Repository-level GitHub Release immutability prevents replacement of the tag
  or uploaded assets after publication.
- The updater performs a planned version switch with restart safety checks,
  health verification, and rollback support.
