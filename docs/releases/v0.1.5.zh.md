# Aria Internal v0.1.5

> 本文是 [`v0.1.5.md`](v0.1.5.md) 的中文版。

Aria 0.1.5 强化了外部渠道与诊断消费方使用的运行时边界。它增加了可扩展的
引擎契约，扩展了 Native Read 投影，并让微信客服链路在答案生成、投递与
图片处理上具备持久性。

本内部快照通过 GitHub 仓库分发，不发布到 npm。

## 新增

- 定义了能力驱动的 Agent 运行时契约，使引擎专属的模型、推理、服务层级与
  会话行为可以演进，而不必在渠道层散布引擎条件判断。
- 将消息身份与会话目录数据并入 Native Read，同时保持只读诊断边界。
- 新增确定性的微信客服会话命令，以及可注入的渠道专属展示规则。
- 新增入站 JPG/PNG 附件接收，以及通过共享媒体边界的持久化出站图片投递。

## 可靠性

- 微信客服答案在投递前先落检查点，瞬时发送失败不会丢失已完成的工作。
- 为微信客服渠道新增持久化回执、收件箱状态、引导状态与投递恢复。
- 出站微信客服文本经专用纯文本展示适配器渲染，处理中反馈只作用于
  符合条件的提问。
- 通过短 POSIX socket 路径与原生 Windows 命名管道路径，恢复了 Native
  Read 在 Linux、macOS 与 Windows 上的 HTTP 启动。
- 后台卡片动作测试改为等待已注册的完成边界，并限制 Windows 测试并行度，
  消除了调度相关的失败。

## 升级指引

- 在常规升级预检确认没有进行中的会话后，全局 Aria 安装请使用
  `internal-v0.1.5`。
- 本次升级仅视为 Aria 运行时升级。渠道专属消费方的
  部署仍是独立的运维决策。
- 在升级后健康检查通过前，保留上一个不可变内部版本作为自动回滚基线。

## 分发保证

- 内部发布仅从精确合入的 `main` commit 构建。
- tarball、产物 manifest、校验文件、发布契约与独立安装器在草稿发布前
  均已验证。
- 仓库级 GitHub Release 不可变设置，确保发布后 tag 与上传资产无法被
  替换。
- 升级器执行带重启安全检查、健康验证与回滚支持的计划式版本切换。
