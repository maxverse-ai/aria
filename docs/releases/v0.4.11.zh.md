# Aria v0.4.11

本补丁修复 Windows Codex 桌面更新后，后台 bot 仍绑定已删除可执行文件目录
的问题，并为 Windows 脚本分发加入独立后台健康守护。

- Codex 初始化保留请求的命令，不再永久保存临时发现路径。准备、进程启动、
  历史读取和 doctor 使用一致的发现逻辑。旧桌面版本目录不存在时，可在当前
  用户的原安装位置恢复；独立固定路径和权限错误不会被静默切换到其他安装。
  恢复候选先经过有界版本探测，再进行 App Server 初始化验证。
- 刷新后的 Windows 服务只拥有一个桥接子进程，仅在确定子进程退出后退避
  重试。控制端点未就绪时告警，不强杀活跃或状态未知的任务。保留认证身份
  检查及已有重启准入规则。
- 持久化健康状态和本地告警记录，让 `aria status` 能展示启动失败、子进程
  退出和守护状态过期。可选 HTTPS 飞书自定义机器人 webhook 独立于桥接和
  编码 Agent 发送通知，支持连续故障过滤、持续故障提醒及恢复通知。不会从
  既有聊天推断收件人或复制 bot 凭据。

现有服务需显式刷新启动器并安全重启才能使用新守护。远程告警需运维配置；
安装本身不会启用 webhook 或中断正在运行的 bot。缺少随包守护的编译分发
保持原有服务路径。配置方法见[运维指南](../operate-the-bridge.zh.md)。

验证覆盖确定性的崩溃、就绪和通知回归，以及包含不安全强杀负例的有限
TLA+ 守护模型，并执行仓库完整本地集成和精确主分支发布检查。
进程就绪不代表模型推理或聊天投递成功；守护、整机或网络不可用时仍需
外部监控覆盖。
