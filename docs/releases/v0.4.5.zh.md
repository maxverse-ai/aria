# Aria v0.4.5

> English version: [v0.4.5.md](v0.4.5.md)

Aria 0.4.5 改进 Windows 后台服务自启动可靠性和私有 GitHub Release 的校验。

## 修复

- 启动 Windows 后台服务时，默认保留已有计划任务和已保存的开机启动凭据，同时更新启动脚本。
- 通过 COM/XML 查询 Windows 任务状态，避免依赖英文任务计划程序输出。
- 启用任务失败时停止启动流程，新注册任务通过实际状态校验后才报告成功。
- 本机发布流程在正式发布前，通过 Release ID 检查私有发布草稿及已验证的资产。
- 嵌入式 worker 测试隔离继承的渠道环境变量，并验证 worker 启动时仍会拒绝这些变量。

## Windows 自启动

使用 `aria start --autostart auto|boot|logon` 选择启动模式。默认 `auto` 保留已有任务；新建任务时，在管理员交互式终端中选择开机启动，其他情况选择登录后启动。

配置开机启动需要在本机管理员终端中输入 Windows 账户密码，而非 Windows Hello PIN。显式指定 `boot` 时不会静默降级为登录后启动；`auto` 模式下取消凭据输入则允许配置登录后启动。

`aria status` 及其 JSON 输出会展示实际注册的自启动模式。已有登录任务仍保持登录后启动，需要使用 `aria start --autostart boot` 显式切换。

配置详情见[后台服务操作指南](../operate-the-bridge.zh.md)，本机发布及校验流程见[发布策略](../RELEASE_POLICY.md)。
