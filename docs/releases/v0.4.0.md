# Aria Internal v0.4.0

> 中文版：[v0.4.0.zh.md](v0.4.0.zh.md)

Aria 0.4.0 moves the release line to 0.4 and raises the supported runtime to
Node 24. This is the release the CLI has been announcing since 0.3.2.

Node 20 reached end of life on 2026-04-30 and was still declared as supported,
while the space native-tool helper already required 22 or newer. The build and
CI have run on Node 24 since 0.3.2, so this release only makes the declaration
match what was already true.

This internal snapshot is distributed through the GitHub repository. It
is not published to npm.

## Changed

- `engines.node` is now `>=24.0.0`, and the published bundles target Node 24.
  Installing or updating on Node 20 or 22 is refused by the installer's engine
  check with `release requires Node.js >=24.0.0` rather than failing later.
- The native-tool helper check requires Node 24, so execution spaces no longer
  run a partially supported configuration.
- The CLI notice changes from an advance warning to a statement of the current
  requirement: `Aria requires Node 24 or newer; this host runs v<version>`.

## Upgrade guidance

- **Move the host to Node 24 first.** The installer refuses this release on an
  older runtime, so an update planned before the runtime moves cannot apply.
- Then use `aria update plan --target-version 0.4.0` and apply the generated
  plan. The apply operation is detached; follow the durable operation id rather
  than assuming a lost terminal means failure.
- Keep the immutable `internal-v0.3.2` installation as the rollback baseline
  until supervisor, profile, channel, and console health checks pass.

## Inherited

0.4.0 carries everything on this line: the execution spaces, channel-free
managed worker, `/task` commands, per-engine permission policy, console
development preview, and channel profile schema v3 from 0.3.0; the detached
Linux updater identity fix from 0.3.1; and the runtime-only Node 24 move and
suite timeout budget from 0.3.2.
