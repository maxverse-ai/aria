# Aria v0.4.9

> 中文版：[v0.4.9.zh.md](v0.4.9.zh.md)

Aria 0.4.9 fixes ownership races in follow-up mail delivery, execution capacity,
Codex reconnection and card callbacks.

- Mailbox consumers exclusively claim each body across processes. Known task
  rejection releases the claim; unknown submission outcomes remain retained
  for inspection and are not automatically replayed. Stable request IDs no
  longer resurrect consumed messages.
- Process-pool permits are reserved for waiting callers before they wake, and
  repeated release cannot free another run's capacity.
- Codex engine-initiated turn subscriptions attach to replacement clients after
  reconnect and detach from closed clients.
- Card actions return before dispatcher I/O begins and continue through the
  shared ordered background executor.
- Legacy installation adoption probes the actual CLI version and resolves npm
  command shims, preserving a verifiable rollback baseline when package metadata
  and executable versions differ.

TLA+ checks include mailbox owner death and uncertain submission. Real component,
subprocess and run-flow regressions verify the corrected boundaries. These do
not establish exactly-once agent effects, model receipt of CLI output, or live
Feishu acknowledgement latency. See [repair evidence](../RUNTIME_OWNERSHIP_IMPLEMENTATION.md)
and [mailbox recovery limits](../STEERING.md).
