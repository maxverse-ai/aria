# Aria Internal v0.3.0

> 本文是 [`v0.3.0.md`](v0.3.0.md) 的中文版。

Aria 0.3.0 把发布线从 0.2 推进到 0.3。它新增了执行空间、无渠道的受管
worker，以及支撑它们的权限、任务与控制台工作。

执行空间是显式的。没有任何东西会自动迁移，它要求 `mode: team`，现有
profile 数据在被受信适配器导入前保持封存。

执行空间要求 Linux 主机。在其他系统上准备或读取会以
`execution spaces require a Linux host` 关闭失败，而不是降级运行。

本内部快照通过 GitHub 仓库分发，不发布到 npm。

## 新增

- 新增 `aria space` 管理执行空间生命周期：`status`、`rollback`、
  `prepare <deployment-file>`、`prepare-upgrade <deployment-file>`、
  `activate <selection-file>` 与 `inspect <selection-file>`。准备过程
  离线且可审查；激活在 profile 停止时进行。
- 新增 `aria worker discover` 与 `aria worker serve`，把 Aria 作为无渠道
  受管 worker 运行，通过 stdin/stdout 说换行分隔的 JSON-RPC。
- 新增 `aria profile start <name>`。交互式 `aria profile create` 现在会
  在现有 Supervisor 上启动新 profile；`--no-start` 只保存不启动，非交互
  脚本默认只保存，除非传 `--start`。
- 新增 `/task` 会话命令，用于被接纳的多参与方工作：`ask`、`join`、
  `leave`、`list`、`status`、`notes`、`transcript`、`change`、`use`、
  `save`、`remove`、`submit`、`stop` 与 `cancel`。
- 新增按引擎的权限策略，以及原生引擎运行时启动所经过的执行空间进程
  边界。
- 新增控制台开发预览：提供与打包控制台相同的 `web/` 源码，默认只读，
  写入需要显式放开。

## 变更

- 移除了 `bubblewrap` 执行空间驱动。`trusted-process` 与容器
  （`execution`）驱动保留；省略驱动或指定未知驱动的部署会被拒绝，而不是
  在不受约束下运行。
- 执行空间声明为仅 Linux。其余空间宿主从未能满足该功能的 unix-socket
  传输与容器驱动，此前只会报一个无关的 bind 或路径错误。
- 渠道 profile schema v3 作为显式 opt-in 迁移提供。schema v2 仍是默认，
  读取绝不改写字节，也没有任何在线 profile 会被隐式迁移。
- Supervisor 启动失败的 profile 会保留已保存的配置并报告重试命令，
  而不是丢弃该 profile。
- Supervisor 重启只恢复被明确要求运行的 profile。被显式停止的 profile
  保持停止。

## 升级指引

- 现有 Lark profile 无需任何改动。执行空间是显式的"准备并激活"步骤，
  绝不是自动迁移。
- 声明了 `driver: "bubblewrap"` 的部署必须迁移到 `trusted-process`
  （空间持有状态、共享主机 OS 访问）或容器驱动（隔离）。
  `trusted-process` 不构成 OS 或凭证隔离边界。
- 请在隔离的工作空间中准备并检查部署文件，不要直接改已安装的运行时。
- 控制台预览视为开发面。它与打包控制台共享 `web/`，两者不得漂移。
- 在 supervisor、profile、渠道与控制台健康检查通过前，保留不可变的
  `internal-v0.2.2` 安装作为回滚基线。
