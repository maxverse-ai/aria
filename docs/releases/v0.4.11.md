# Aria v0.4.11

This patch prevents Windows Codex desktop updates from leaving unattended bots
pinned to a removed executable directory and adds an independent background
health host to packaged Windows script installations.

- Codex bootstrap preserves the requested command instead of persisting a
  transient discovery result. Preparation, process startup, history and doctor
  use the same discovery behavior. Missing legacy desktop hash paths can recover
  within the current user's canonical installation; independent pinned paths and
  permission failures do not silently switch installations. Recovery candidates
  receive bounded version probes before App Server initialization.
- Refreshed Windows services own one bridge child and retry only after definitive
  child exit, with bounded backoff. Failed control readiness alerts without
  killing active or unknown work. Runtime controls retain their existing
  authenticated identity checks and restart admission rules.
- Persistent health and local alert records expose startup failure, child exit
  and stale host state through `aria status`. Optional HTTPS Feishu custom-bot
  webhooks deliver alerts without the bridge or coding agent, with consecutive
  failure filtering, reminders and recovery notifications. No recipient or bot
  credential is inferred from existing chats.

Existing services require an explicit launcher refresh and safe restart to use
the new host. Remote alerts require operator configuration; installation does not
enable a webhook or interrupt a running bot. Compiled distributions without the
packaged host retain their original service path. See the
[operations guide](../operate-the-bridge.md#windows-background-health-and-alerts).

Validation covers deterministic crash/readiness/notification regressions and a
finite TLA+ host model with an unsafe health-kill negative control, alongside the
repository's complete local integration and exact-main release gates. Process
readiness is not proof of model inference or chat delivery; external monitoring
is required when the host, machine or network is unavailable.
