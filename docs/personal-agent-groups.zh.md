# 个人 agent 群

> Status: current

> 本文是 [`personal-agent-groups.md`](personal-agent-groups.md) 的中文版。

当以下条件全部满足时，Aria Supervisor 管理的个人 profile 会在一个"恰好一
个人类 + 至少两个 agent"的群里自动放行被显式提及的消息：

- 一份完整且新鲜的 provider 成员名单能识别每个成员，包括本 bot。
- 该人类是本 profile 已验证的运行时 owner，或已配置的管理员。
- 每个 bot 都是同一 Supervisor、同一飞书 / Lark 域内已认证且当前在线的
  渠道。
- 发送者的 provider 身份与该人类或某个参与中的 bot 匹配。

这类群不需要 `/invite group`。`/status` 会说明自动放行当前是否可用。显式
提及仍然决定由哪个 agent 回应；"一个人类 + 一个 bot"的寻址规则不变。bot
消息不会获得管理员权限。

信任注册表归 Supervisor 持有：在渠道连接后填充，断连时移除。它从不信任
显示名、消息文本、任意的名单成员关系，或配置里对外部 bot 的声明。首个实现
不会自动信任其他 Aria 进程或外部平台里的 bot —— 它们仍走既有的手动群
授权流程。

自动放行不会写入 `allowedChats`。那份不透明的听众证明随排队输入一起传递，
在启动模型前重新校验，并在最终历史检查之后、发布之前再次校验。出现新的
人类成员、未知 bot、断连的对端、被撤销的管理员/owner 权限，或不完整的名单
证据时，自动放行立即中止。被自动放行的输入保持排队，不会去 steering 一个
持有不同听众证明的活跃运行。这些运行复用既有的协作式"只回终稿"路径和
结构化 handoff，因此中间模型输出不会流给正在变化的听众。

已手动开启的群和团队执行空间保留各自现有策略。自动放行只授予 IM 使用权；
它不改变引擎工具权限、用户 OAuth 凭证、执行空间绑定或跨 agent 任务授权。
既有的协作回复与新鲜度检查仍然生效。

`/invite group` 仍是显式的持久群授权。`/remove group` 移除该持久授权；
它不是一条拒绝规则，也不能覆盖自动放行资格（正如它无法撤销既有的
owner/admin 旁路）。
