# Space 内直接运行 CLI：实施与迁移计划

日期：2026-09-11。状态：已授权实施，开发中，未集成、未上线。

## 目标和边界

Aria 核心负责真实消息主体、Space 准入、任务调度、执行环境、持久存储及资源限制。CLI 在 Space 容器内执行并访问外部服务。业务命令、OAuth、凭据刷新交给具体 CLI；工具包提供安装、初始化和 Agent 说明。飞书消息渠道仍保留。

一个 Space 一个执行环境。HOME、工作文件和会话持久保存；个人配置不共享，镜像不包含凭据，管理 socket 和控制侧 profile 不暴露给 Agent。允许联网不等于允许 host 网络命名空间。bridge 本身不是出口 ACL，也不保证跨容器网络阻断；部署必须单独验证管理服务及跨 Space 网络边界。

## 已核实的身份限制

当前 CLI 帮助说明 strict-mode 支持 bot/user/off，切换不要求重新绑定。可写配置和命令包装器无法保证 Agent 不能解除规则。用户已明确接受默认配置正确、用户管理自己 Space 内的账号。群默认 bot，个人默认 user，不再由 Aria 强制锁定登录账号；Space 准入和存储边界不变。

容器内可访问的凭据对本 Space Agent 可见；本设计不再声称原始凭据始终只留在控制侧。容器之间的隔离不自动校验 OAuth 登录的人是谁。

## 分阶段交付

1. 通用执行网络：明确 none/bridge 部署意图；保留非 root、只读根、cap-drop、no-new-privileges、资源限制；网络变更进入环境指纹，停止并重建旧实例，不修改现有线上配置。
2. 工具环境：镜像固定 CLI 版本；按 Space 初始化私有 HOME 和配置；工具说明使用稳定 CLI 命令；核心不增加新 CLI 专用参数解析。
3. 身份契约：采用用户已确认的默认身份；保留说明和用户账号管理能力，不把 strict-mode 或提示词描述为强制边界。不自行更换现有 channel/profile 或解除绑定。
4. 数据迁移：排空单个 Space、备份、复制工作文件/兼容会话；单独验证 CLI 凭据格式、加密依赖、绑定和真实身份。不能复制整个控制侧 profile。无法恢复的个人登录态在私聊重新授权。禁止新旧实例同时刷新一份凭据。
5. DeepSeek 验收：个人/共享 Space 真实调用、上传下载、登录恢复、跨 Space 文件和网络隔离、错账号处理、撤销/过期、并发和回滚。
6. 切换及清理：仅 DeepSeek 首批；通过验收后切换。删除无调用方的 Lark 控制侧代执行、参数转发和旧凭据槽；保留其他工具使用的通用服务。旧登录目录不能在验收前删除。

## 验证记录

- 已检查当前 Podman 适配器：原网络仅允许 none，create 参数固定 --network=none。
- 已检查 CLI config strict-mode 帮助：支持修改身份策略，不能独自满足不可绕过规则。
- 开发中的网络支持只提供显式 none/bridge 选择；生产网络尚未放开。
- 当前线上继续使用既有控制侧 Lark 代执行链路，尚未迁移凭据。

## 通用包接口（第一阶段代码）

部署可选 environmentPackages，条目包含 id/revision/module/sha256，模块和依赖随不可变镜像交付。模块提供 environmentPackageRevision 和 prepareSpaceEnvironment(context)。context 包含可信 SpaceKey、profileId、SpacePaths、取消信号；返回 environment 和 instructions。核心在获得容器独占权之后、启动 Agent 之前准备，拒绝配置冲突和启动钩子变量，说明随每轮请求呈现。包自行确保初始化幂等，保留用户之后选择的账号，不执行后台任务。包是可信部署代码，不是从用户 workspace 加载的插件。

现有 tools 只用于仍在使用的控制侧工具。新部署省略 tools，即不注册 Lark 控制侧调用服务。其他既有部署兼容保留，未迁移前不能直接删除对应实现。

DeepSeek 下游已用不重叠的路径申请独立开发租约，初始化工具包和部署配置正在验证。旧个人授权迁移通过公开的过渡接口复制已完成授权对应的配置及加密存储，保留原文件；不导入未完成授权、日志或其他账号目录。迁移失败保留现场，不自动合并或覆盖用户状态。真实容器联网、登录恢复和上线仍须独立验收。
